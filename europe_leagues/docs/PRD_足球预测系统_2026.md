## 4. 系统总体架构

### 4.1 分层

1. **入口层**：`prediction_system.py`、`app/cli.py`
2. **编排层**：`domain/predictor.py`、`enhanced_prediction_workflow.py`
3. **领域层**：`domain/live.py`、`domain/inference.py`、`domain/postprocess.py`、`domain/rag.py`、`domain/persistence.py` 等
4. **采集层**：`collectors/*` 与保留的 `okooo_*` 脚本
5. **存储层**：`storage/*`、`runtime/*`、`result_manager.py`
6. **运行时资产层**：`.okooo-scraper/schedules/`、`.okooo-scraper/snapshots/`、`.okooo-scraper/runtime/`

### 4.2 关键 owner

- 预测 side effects owner：`domain/persistence.py`
- 结果同步 owner：`runtime/result_sync.py`
- 结果归档 / 准确率 owner：`result_manager.py`
- 真实 CLI 命令 owner：`app/cli.py`

### 4.3 三轴影子诊断层（纯标记，不改方向）

`domain/inference.py` 在主预测之外产出 `tri_axis_consistency` 影子诊断层：汇总方向轴/大小球轴/操盘轴 + 临场资金轴（封盘热门赔率漂移），做一致性与背离标注。操盘轴含「让球方向手法矩阵」（亚盘升降盘 × 水位档位 × 欧赔方向 → 阻上/诱上/防客/诱客/阻下，以「让球口诀」并入研判文本）。**纯诊断：不改任何概率/方向、不加权**（各信号同源市场、高度相关，加权会重复计价）。

其中临场资金轴带**置信度质检层**：欧赔走冷信号用亚值/凯利同向印证（`drift_confidence` = high/low/n/a），过滤单家欧赔抓取噪声；大小球漂移作为独立维度单独记录。整层随 `tri_axis_consistency` 持久化到 archive 供回测。技术口径见架构文档 3.7 节。

## 5. SoT 写回边界（二元）

写回边界已收敛为二元：**只有 SoT-backed 正式联赛走完整写回；其余赛事走 `archive_only`（仅归档 + 赛果同步 + 准确率，不写 MEMORY/RAG/teams md）。**

### 5.1 SoT-backed competitions（唯一允许写回）

以下且仅以下 competition 允许写回 teams md / `MEMORY.md` 滚动记忆 / RAG / 赛果同步登记：

- `premier_league`
- `la_liga`
- `serie_a`
- `bundesliga`
- `ligue_1`
- `world_cup`

对应事实源：

- 五大联赛：`<league>/teams_2025-26.md`
- 世界杯：`world_cup/teams_2026.md`

判定逻辑见 `app/cli.py` 的 `SOT_BACKED_LEAGUE_CODES` 与 `is_sot_backed_league()`。

### 5.2 其余一切赛事（仅归档同步，不写 MEMORY/RAG/teams md）

欧战（`europa_league` / `champions_league` / `conference_league`）、其他杯赛、友谊赛（`friendly`）以及任何非上述六个联赛的 competition：

- `predict-match` 走 `archive_only` 路径（`persist=True, archive_only=True`），**只归档预测 + 登记赛果同步 + 刷新准确率/仪表盘，不写 teams md、不写 `MEMORY.md`、不进 RAG**
- 结果标记 `persisted.archive_only = True`、`persisted.memory_updated = False`、`persisted.archived = True`
- 对应实现：`domain/persistence.py` 的 `persist_archive_only_prediction()`
- 直接跑 `okooo_save_snapshot.py` 快照脚本本就不碰 `MEMORY.md`，只落 `.okooo-scraper/snapshots/`

> **世界杯是 SoT-backed 正式联赛**：它在 SoT-backed 列表内、归档文件为 `world_cup/teams_2026.md`。`predict-match` 会写回正式联赛主归档 + 滚动记忆 + 赛果同步登记。

## 6. 端到端正式流程

### 6.1 赛前流程

1. `collect-data` 获取赛程、`match_id`、上下文与可复用快照信息
2. `predict-match` 执行预测（足彩 14 场用 `predict-fourteen-issue`）
3. 通过 `domain/persistence.py` 处理 SoT 写回（archive、MEMORY、RAG、registry side effects）；非 SoT 赛事只输出不写回
4. 如需阶段化审计，使用 `harness-run`

### 6.2 赛后流程

1. `pending-results` 查看待回填比赛
2. `auto-sync-results` 尝试自动同步
3. 未命中时使用 `save-result` 手工补录
4. 如需批次回填 + 复盘，总入口为 `sync-pending-results-review`
5. 如需显式重建统计，再执行 `accuracy --refresh`

### 6.3 自动闭环事实

正常赛果闭环后，系统会推动多项衍生产物刷新，包括但不限于：

- SoT 比分 / 备注
- `MEMORY.md`
- `prediction_archive.json`
- 准确率统计
- RAG 记忆样本与索引
- review-learning 相关输出

因此 `accuracy --refresh` 是显式重建入口，不应被描述成唯一常规路径。

### 6.4 Replay / Reanalysis 显式应用流

`reanalysis_results*.json` 代表当前模型对历史样本的 replay 结果，它们本身不会自动覆盖正式记录。`apply-reanalysis` 是受控维护入口，用来把选中的 replay 预测显式提升为正式记录。

对 SoT-backed 联赛，这个过程会同时更新：

- `prediction_archive.json` 中对应比赛的正式预测记录
- `<league>/teams_2025-26.md` 中对应比赛备注里的预测片段

因此 replay apply 的目标是“对齐正式数据源”，而不是通过改读取优先级来偷换官方准确率口径。

## 9. 当前风险与治理重点

当前最容易产生漂移的区域不是模型本身，而是“说明口径”：

- 文档把兼容入口写成主逻辑
- 文档和 skill 引用了失效路径
- README / guide / PRD / skills 对 SoT 写回与非 SoT `archive_only` 的描述不一致
- 开发态 Python 调试示例被误当成正式使用方式

治理原则：

- 入口说明以 `app/cli.py` 为准
- 结果闭环说明以 `domain/persistence.py`、`runtime/result_sync.py`、`result_manager.py` 为准
- replay/apply 语义以 `result_manager.py` 与 `domain/writeback.py` 为准
- 技能说明与文档统一采用 CLI-first 叙述
- repo-local 路径必须真实存在，否则删除引用

---

## 10. 验收标准

文档与 skill 收口完成后，应满足：

1. 仓库内不再出现“正式入口是谁”的多套说法
2. 文档列出的正式命令都真实存在于 `app/cli.py`
3. 文档中的 repo-local 路径都真实可达
4. README / guide / PRD / skills 对 SoT 写回边界（二元：仅 SoT 写回，其余只输出）说法一致
5. README / guide / PRD 对官方准确率与 replay 准确率的描述一致
6. `apply-reanalysis` 被描述为显式维护流，而不是默认赛后自动路径
7. 默认示例以 CLI 为主，底层 Python import 只保留给调试说明
